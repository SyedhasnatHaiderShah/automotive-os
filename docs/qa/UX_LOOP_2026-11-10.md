# UX quality loop — 2026-11-10

Branch `ux/all-flows-quality-loop`. Local stack only: `automotive_os_qa`, API as `automotive_app_user`
(RLS enforced), `DEALER_AUTH_ENFORCED=true`, no admin dev bypass, no object storage, `next dev` servers.
Nothing here is a claim about staging or production.

## Method

Harness: `tests/e2e/ux-loop/run.cjs` (Playwright, Chromium).

- Fresh state: each role flow starts in a new browser context with no cookies, storage or saved login,
  and signs in through the real `/auth` form.
- Flows: anonymous (20 URLs), buyer (7), dealer owner (16), platform admin (12). 55 URLs.
- Sizes: 1440x900, 768x1024, 375x812. Modes: English LTR, Arabic RTL. 330 screens per pass.
- Every screen is scored with the same 12 checks, one point each:
  loads, no script errors, no failed requests, no horizontal scroll, one `main` and one `h1`,
  specific title, every control named, images have alt and render, 24px tap targets (mobile),
  WCAG AA text contrast, `lang`/`dir` match the language, visible keyboard focus (desktop English).

## Changes

- **Missing photos** (48 screens): new `MediaImage` in `packages/ui` shows a labelled placeholder when a photo
  cannot be loaded. Used on the vehicle page, enquiry dialog, compare, saved cars, garage, dealer storefront,
  dealer inventory and admin listing review. Before, the browser's broken-image icon and alt text showed.
- **Landmarks** (90 screens): `main` added to verify-email, activate, access-denied, access-suspended and the
  dealer not-found page (which also gets an `h1`); the standalone enquiry route gets `main` and a
  screen-reader `h1`.
- **Contrast** (54 screens): grey text at 3.97:1 on the auth footer, password rules, access pages and two admin
  tables raised to 4.5:1 or better.
- **Tap targets** (54 screens): breadcrumbs, "Forgot passcode?", show-password toggles, "View all" links, admin
  language buttons, admin data links, buttons and checkboxes are at least 24px. The show-password toggle now
  sits on the trailing edge in Arabic.
- **Horizontal scroll** (12 screens): `/cars` toolbar and admin users filters wrap on phones; admin data tables
  keep their screen-reader labels inside the scroll area.
- **Auth header** (found by eye, not by the checklist): the last header link was clipped at 375px in both
  languages. It now fits; the tagline is hidden below the `sm` breakpoint.

## Measurement corrections made before the baseline was accepted

The first run of the harness scored 91.18% and was discarded because it measured wrongly:

- It counted the Next.js dev indicator as an unfocusable control.
- It counted 404s for seeded photo URLs as failures. The local stack has no object storage, so those
  requests cannot succeed; what the user sees (a broken image) is scored instead.
- It ignored landmarks behind an open dialog.
- The admin app was started without `JWT_SECRET`, so admin sign-in looped and the admin flow was not scored.
- It treated the nine preview-module routes as live pages. They are switched off by design unless
  `NEXT_PUBLIC_ENABLE_PREVIEW_MODULES=true` (DL-07), so each is now expected to show the not-found page.

## Limits

- 100% means the 12 checks pass on these 330 screens. It is not a full accessibility audit: the contrast check
  skips text over images, gradients and blurred backdrops, and nothing here tests a screen reader.
- The preview modules were scored only as not-found pages, not as working screens.
- `/admin/moderation/listings/[id]` was not reached: the moderation queue had no listing link to follow.
- States behind actions (form errors, empty lists, dialogs other than intake and enquiry) are not covered.
- Widths below 375px are not covered; at 320px the auth wordmark is tight.
