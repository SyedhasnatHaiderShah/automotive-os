## Addendum 2026-11-06 — platform-admin data console (AD-20)
Request: platform admins can create, read, update and delete rows of every table from the UI, verified in a browser.

Built:
- API `GET /api/v1/admin/data/models`, `GET :model/schema`, `GET :model` (page/limit≤100/q/sort/dir), `GET :model/:id`, `POST :model`, `PATCH :model/:id`, `DELETE :model/:id {reason}` — `apps/api/src/admin/data/` (registry from the Prisma DMMF, service, controller, DTOs). Guards: JWT + active platform admin; model names validated against the schema; ids UUID-shaped; secrets (`passwordHash`, `mfaSecret`, `emailVerificationTokenHash`, session/invitation `tokenHash`) never read or written; ids/timestamps read-only; values coerced (BigInt, DateTime, Decimal, enums, lists, JSON) with per-field errors; unique → 409, FK → 400; every mutation writes `PLATFORM_ADMIN_DATA_CREATE/UPDATE/DELETE` audit rows in the same transaction; deleting your own user or the last active admin is refused.
- Admin UI `/admin/data` (table index with live counts), `/admin/data/[model]` (search, sort, pagination, delete with mandatory reason), `/admin/data/[model]/new` and `/admin/data/[model]/[id]` (form generated from field metadata), sidebar entry "Data Console", EN/AR. The page carries a standing notice that raw edits bypass workflow rules but are audited.

Fixed by migration `20261106090000_admin_catalog_write_policies` and `tenant_policies.sql` (admin write policies).
